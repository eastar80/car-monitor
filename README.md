# 차량 지출 관리 (차계부)

주유와 지출을 기록하고 통계를 보는 개인용 차계부입니다.
서버 없이 브라우저 안에서만 동작하는 PWA라서, 폰 홈화면에 설치해 오프라인에서도 쓸 수 있습니다.

- 사용자 1명, 로그인·계정·서버 없음
- 데이터는 브라우저의 IndexedDB에만 저장되고, JSON 파일로 백업·복원합니다
- 한국어 UI, 원(₩) / km / L

---

## 1. 실행 방법

Node.js 20 이상이 필요합니다.

```bash
npm install       # 처음 한 번
npm run dev       # 개발 서버 (http://localhost:5173)
npm test          # 계산 규칙 단위 테스트
npm run build     # 배포용 파일을 dist/ 에 만듦
npm run preview   # 만들어진 dist/ 를 그대로 띄워서 확인
```

폰에서 확인하려면 폰과 PC가 같은 와이파이에 있을 때
`npm run dev -- --host` 로 띄우고 폰 브라우저에서 PC의 주소로 접속하면 됩니다.

### 폰 홈화면에 설치하기

배포 주소에 Chrome으로 접속 → 오른쪽 위 ⋮ → **앱 설치**(또는 홈 화면에 추가).
설치하면 주소창 없이 앱처럼 열리고, 비행기 모드에서도 켜집니다.

## 2. 배포 방법 (GitHub Pages)

`main` 브랜치에 push하면 `.github/workflows/deploy.yml`이 테스트를 돌리고 자동으로 배포합니다.

**처음 한 번만** 저장소에서 아래를 설정해 주세요.

1. GitHub 저장소 → **Settings** → **Pages**
2. **Source**를 `Deploy from a branch`가 아니라 **`GitHub Actions`** 로 바꾸기
3. `main`에 push하면 **Actions** 탭에서 진행 상황이 보이고, 끝나면 주소가 나옵니다

주소는 `https://<깃허브아이디>.github.io/car-monitor/` 형태입니다.

> 저장소 이름을 `car-monitor`가 아닌 것으로 바꾸면
> `vite.config.ts`의 `base` 값도 같이 바꿔야 합니다.

## 3. 백업 파일 구조

설정 → 데이터 → **백업 파일 만들기**를 누르면 JSON 파일 하나가 만들어집니다.
이 파일 하나가 앱의 전체 상태입니다.

- 파일 이름: `car-expense-backup-2026-09-30.json`
- Android Chrome에서는 공유 시트가 떠서 구글 드라이브·카카오톡 등으로 바로 보낼 수 있고,
  공유를 지원하지 않는 브라우저에서는 그냥 다운로드됩니다

```jsonc
{
  "schemaVersion": 1,              // 앱이 읽을 수 있는 형식인지 판단하는 번호
  "exportedAt": "2026-09-30T…",    // 백업을 만든 시각
  "vehicles":   [ /* 차량 */ ],
  "groups":     [ /* 카테고리 그룹: 차량구입·고정비·소모품·수리·기타 */ ],
  "categories": [ /* 지출 카테고리 + 교환주기 */ ],
  "fuelLogs":   [ /* 주유 기록 */ ],
  "expenses":   [ /* 지출 기록 */ ]
}
```

레코드 한 건은 이런 모양입니다. 모든 레코드가 `id`(UUID)와 `updatedAt`을 가지고 있어서,
나중에 온라인 DB로 옮기거나 두 기기의 백업을 병합할 때 그대로 쓸 수 있습니다.

```jsonc
// fuelLogs 한 건
{
  "id": "…", "vehicleId": "…",
  "date": "2026-06-16",      // YYYY-MM-DD
  "odometer": 42249,          // 주유 시점 총주행거리 (km)
  "pricePerLiter": 1995,      // 리터당 가격 (원)
  "totalPrice": 85000,        // 주유 금액 (원)
  "liters": 42.61,            // 금액 ÷ 단가 (직접 고칠 수 있음)
  "station": null, "memo": null,
  "updatedAt": "2026-06-16T…"
}

// expenses 한 건
{
  "id": "…", "vehicleId": "…", "categoryId": "…",
  "date": "2026-04-15",
  "odometer": 41000,
  "amount": 22330,            // 금액 (원)
  "place": null,
  "memo": "전우",
  "updatedAt": "2026-04-15T…"
}
```

### 복원

설정 → 데이터 → **백업 파일에서 복원** → 파일 선택 → 미리보기 확인 후

- **병합하기** — 같은 `id`면 `updatedAt`이 최신인 쪽을 남기고, 없는 기록은 더합니다
- **기존 데이터 지우고 복원** — 지금 기기의 기록을 지우고 백업 내용으로 통째로 바꿉니다

PC에서 통계를 크게 보고 싶을 때도 같은 주소로 접속해 백업 파일을 복원하면 됩니다.
PC와 폰은 자동으로 맞춰지지 않으니, 폰에서 계속 입력하실 거라면 PC에서는 보기만 하세요.

## 4. 기존 엑셀 가져오기

설정 → 데이터 → **엑셀(.xlsx) 가져오기**.

- 시트 이름은 상관없습니다. 헤더에 `리터당가격`이 있으면 주유 시트,
  `항목명`이 있으면 지출 시트로 알아봅니다
- 항목명은 자동으로 카테고리와 메모로 나뉩니다
  - `라이트(전우)` → 카테고리 `라이트`, 메모 `전우`
  - `예열플러그 4개` → 카테고리 `예열플러그`, 메모 `4개`
  - `라이트 전좌` → 괄호를 빠뜨린 것으로 보고 `라이트` + 메모 `전좌`
- 목록에 없는 이름은 **기타** 그룹에 새 카테고리로 만들고, 가져오기 전에 알려줍니다
  (가져온 뒤 설정 → 카테고리 관리에서 그룹을 바꾸면 됩니다)
- 날짜·금액을 읽을 수 없는 행은 건너뛰고 몇 행이 왜 빠졌는지 보여줍니다
- 가져오기 전에 **추가하기 / 지우고 가져오기**를 고릅니다.
  같은 파일을 두 번 "추가하기"로 넣으면 기록이 중복되니 주의하세요

## 5. 계산 규칙

`src/lib/calc.ts`에 모아 두었고, `src/lib/__tests__/calc.test.ts`에 테스트가 있습니다.

**연비 (km/L)** — 주유 건별로는 계산하지 않습니다. 잔량을 모르기 때문에 건별 값은 믿을 수 없습니다.

```
연비 = (마지막 주유 odometer − 첫 주유 odometer) ÷ Σ liters(마지막 건 제외)
```

마지막에 넣은 기름은 아직 쓰지 않았으므로 분모에서 뺍니다.
기간 안에 주유 기록이 3건 미만이면 "데이터 부족"으로 두고 계산하지 않습니다.

**교환주기 잔여량** — 카테고리의 가장 최근 지출을 "마지막 교환"으로 봅니다.

```
잔여 km   = 마지막 교환 odometer + intervalKm − 현재 주행거리
잔여 일수 = (마지막 교환 date + intervalMonths) − 오늘
```

둘 다 있으면 먼저 도래하는 쪽이 기준입니다.
상태는 정상(잔여 10% 초과) / 임박(10% 이하) / 초과(음수) / 기록 없음입니다.

**월별 집계** — 월 귀속은 `date` 기준이고 `odometer`는 쓰지 않습니다.
**차량구입** 그룹은 월별·연도별·비중 그래프와 요약 숫자에서 빠지고, "전체 보유비용"에만 들어갑니다.

**현재 주행거리** — 따로 저장하지 않고, 그 차량의 주유·지출 기록 중 가장 큰 `odometer`로 계산합니다.

## 6. 쓰는 라이브러리와 이유

| 라이브러리 | 왜 쓰나 |
| --- | --- |
| React + TypeScript | 화면을 조각으로 나눠 만들고, 타입으로 데이터 실수를 미리 잡으려고 |
| Vite | 개발 서버가 빠르고 설정이 적어서 |
| Dexie.js | 브라우저 IndexedDB를 직접 다루면 코드가 길어져서, 테이블·인덱스를 짧게 선언하려고 |
| Recharts | React로 만든 화면에 그래프를 그대로 끼워 넣을 수 있어서 |
| Tailwind CSS | 별도 CSS 파일 없이 모바일 우선 반응형 레이아웃을 빠르게 짜려고 |
| vite-plugin-pwa | 홈화면 설치와 오프라인 동작(서비스워커)을 자동으로 만들어 줘서 |
| SheetJS (xlsx) | 기존 .xlsx 파일을 서버 없이 브라우저에서 바로 읽으려고 |
| Vitest | 계산 규칙 테스트용. Vite 설정을 그대로 쓸 수 있어서 |
| fake-indexeddb | 테스트는 브라우저 밖에서 도는데 IndexedDB가 필요해서 (테스트에서만 씀) |

## 7. 파일 구조

```
src/
  main.tsx              앱 시작점. 첫 실행이면 기본 데이터를 만든 뒤 화면을 띄움
  App.tsx               하단 탭 4개와 화면 이동(라우팅)
  types.ts              데이터 모델 (Vehicle / FuelLog / Expense / Category / Group)
  db.ts                 IndexedDB 테이블 선언, 첫 실행 시드, 활성 차량
  seed.ts               초기 그룹·카테고리 표와 그래프 색
  hooks.ts              화면에서 쓰는 데이터 조회
  lib/
    calc.ts             5절 계산 규칙 (연비·원/km·교환주기·월별 집계)
    date.ts             날짜 계산 도우미
    format.ts           금액·거리 표시 형식
    backup.ts           백업 JSON 만들기/복원, 엑셀 결과를 DB에 반영
    excel.ts            .xlsx 읽기와 항목명 나누기 (DB를 건드리지 않는 순수 함수)
    __tests__/          단위 테스트
  components/
    ui.tsx              여러 화면이 함께 쓰는 작은 조각 (입력칸·확인창·목록 줄 등)
    charts.tsx          누적 막대와 도넛 그래프
    RecordItem.tsx      기록 목록 한 줄
  pages/
    Home.tsx  Records.tsx  Stats.tsx
    FuelForm.tsx  ExpenseForm.tsx
    Settings.tsx  VehicleSettings.tsx  CategorySettings.tsx  DataSettings.tsx
```
